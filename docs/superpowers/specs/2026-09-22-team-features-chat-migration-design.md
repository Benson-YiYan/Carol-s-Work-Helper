# 母子版功能迁移与聊天恢复设计

## 目标

将 LCB Work Hub 团队版的当前功能迁移到母子版 `Carol-s-Work-Helper`，让两套网站采用相同的协作、权限和操作机制，但继续使用不同的用户、数据库、文件存储和部署地址。

母子版恢复聊天功能；每周视图不恢复，并删除所有相关入口、路由、文案、样式和教程。

## 迁移基线

- 团队版功能基线：`LCB-Work-Hub` 当前 `main`。
- 聊天恢复来源：本地 Git Bundle `with-chat&weekly.bak` 中删除前的聊天实现。
- 目标仓库：`Carol-s-Work-Helper`。
- 母子版现有用户、事项、客户、文件和日志必须保留。

## 总体架构

两套网站使用相同的前端功能结构，但各自保留独立环境配置。

母子版只能连接母子版 Supabase 项目及其存储桶；团队版只能连接团队版 Supabase 项目及其存储桶。两个网站不共享业务表、认证用户、加密密钥、设备记录、日志或文件路径。

母子版继续采用团队版相同的协作权限：管理员可查看全部事项；普通成员只能查看自己负责或被列入成员列表的事项。文件、动态、通知、聊天引用和已读回执继承对应事项或会话的可见范围。

## 功能范围

### 从团队版同步

- 首页、全文搜索、事项管理、事项工作流程与交接。
- 日历、截止日期计算、工作报告。
- 客户档案、客户跟进、团队负荷。
- 文件上传、版本保留、加密下载与移除。
- 通知、已读回执、批量操作和回收站。
- 登录、设备管理、安全记录、加密备份和数据完整性巡检。
- 中文、英文、西班牙文界面及相应教程。
- 同步频率、冲突检测、运行模式及现有安全防护。

### 恢复聊天

- 群聊消息与自动滚动到底部。
- 保留正在输入的草稿，不因新消息刷新而丢失。
- `@成员`、`屏蔽`、`+` 三个独立按钮及可关闭弹窗。
- 引用事项、步骤、客户档案和事项文件。
- 上传文件并发送。
- 聊天消息、附件、引用内容、屏蔽状态和已读状态按母子版用户及会话权限隔离。
- 恢复聊天的中英西三语文案和教程。

### 明确排除

- 每周视图页面、导航按钮、路由、渲染函数、样式、状态、文案、三语翻译和教程。
- 团队版用户、团队版 Supabase 地址、团队版存储桶和团队版业务数据。

## 配置边界

用户列表、角色、管理员身份、Supabase 地址与匿名公钥、存储桶名称、Turnstile 配置、站点标题和部署基础路径必须集中为母子版配置，不能从团队版硬编码复制。

迁移检查会扫描构建结果，确保其中不含团队版 Supabase 项目标识、团队版存储桶或团队版用户映射。

## 数据与数据库迁移

1. 修改前创建目标仓库 Git Bundle，并记录母子版当前提交。
2. 导出母子版数据库结构与现有数据备份；文件存储不删除、不改路径。
3. 对比团队版与母子版所需表、字段、函数、触发器和 RLS 策略。
4. 使用幂等 SQL 仅新增缺失结构或兼容字段，不清空、不重建现有业务表。
5. 将团队版权限策略转换为母子版用户映射，保持权限行为相同。
6. 聊天数据使用母子版自己的表或兼容记录结构；聊天附件进入母子版存储桶。

任何无法无损升级的结构变化必须停止部署，不以删除旧数据换取迁移成功。

## 前端合并策略

以团队版当前代码为功能主体，再从备份中恢复聊天相关模块；随后将母子版用户及环境配置接回。聊天恢复只引入聊天所需代码，不恢复每周视图。

教程主题、详情数组和路由必须通过测试保持三语数量一致，避免删除或恢复页面后因硬编码索引再次导致白屏。

## 错误处理

- 登录用户不在母子版映射中时拒绝进入，不降级为演示账号。
- 权限不足时不显示数据，直接请求接口也由 RLS 拒绝。
- 同步冲突保留团队版现有版本检查，不静默覆盖他人修改。
- 聊天发送、附件上传或引用读取失败时保留输入草稿，并显示可重试错误。
- 数据库迁移、隔离扫描或正式站运行验证任一失败时停止上线。

## 验证方案

### 自动验证

- 三语教程、路由和页面数量一致。
- 不存在每周视图入口、路由、函数、样式或文案。
- 聊天核心行为测试：草稿保留、消息追加、自动滚底、屏蔽、@成员、引用和附件。
- 登录、同步、版本冲突、通知、文件和本地模式回归测试。
- 构建结果不含团队版后端标识或用户配置。

### 权限与隔离验证

- 管理员能查看母子版全部事项。
- 普通成员只能查看自己负责或参与的事项。
- 非成员无法通过搜索、直接路由、聊天引用或文件地址读取事项。
- 母子版账号不能登录团队版数据空间，团队版账号不能登录母子版数据空间。
- 两套网站新增同名事项、客户和文件后互不可见。

### 浏览器验收

- 在本地真实浏览器完成三种语言及主要页面冒烟测试。
- 使用至少两个母子版账号完成新建事项、分配成员、交接、聊天、引用、上传文件、通知和回收站流程。
- 正式部署后重新执行登录页、核心协作流程和浏览器控制台检查。

## 发布与回滚

先完成本地验证，再应用数据库增量迁移，最后发布母子版静态站。发布期间不修改团队版。

若正式验证失败，静态站回退到迁移前提交；数据库只使用向后兼容的增量结构，因此旧版仍可继续读取原有数据。Git Bundle、数据库备份和原文件存储共同构成回滚基础。

## 完成标准

- 母子版具备团队版当前功能和恢复后的聊天功能。
- 每周视图在代码、界面和教程中完全不存在。
- 母子版原数据完整保留。
- 两套网站的数据、文件、认证用户和密钥完全隔离。
- 自动测试、双账号权限测试和正式站浏览器验收全部通过。
